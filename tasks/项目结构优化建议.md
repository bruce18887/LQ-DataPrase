> 生成时间：2025-06-01  
> 分析范围：后端 apps/ + 前端 frontend/src/ + 根目录文件

## 一、后端结构问题

### 🔴 P0 — 高优先级（必须优化）

#### 1.1 空模型 App（6 个）

**问题：** 以下 app 的 `models.py` 只有占位注释，无实际模型，违反 Django 最佳实践

| App | Models 行数 | Views 行数 | 建议 |
|-----|-----------|-----------|------|
| `batch_report` | 2 | 130 | 降级为 **Feature Module**，合并到 `analysis` 或 `export` |
| `buyoff` | 2 | 110 | 降级为 **Feature Module**，合并到 `export` |
| `dashboard` | 2 | 231 | 保留（有实际业务逻辑） |
| `gage` | 2 | 49 | 降级为 **Feature Module**，合并到 `analysis` |
| `export` | 2 | 150 | 保留（有实际业务逻辑） |
| `sftp` | 2 | 103 | 保留（独立功能） |
| `data_correlation` | 0 | 81 | 降级为 **API Endpoint**，合并到 `analysis` |

**优化方案：**

```
当前：apps/batch_report/views.py (130 行)
优化：apps/export/batch_features.py (功能模块)

当前：apps/gage/views.py (49 行)
优化：apps/analysis/services/gage_rr.py (统计服务)

当前：apps/data_correlation/views.py (81 行)
优化：apps/analysis/views.py 新增 correlation_analyze action
```

**收益：**
- 减少 4 个 Django app，降低维护成本
- 减少路由注册点，简化 `config/urls.py`
- 避免"空模型反模式"

## 三、重复代码识别

### 🔴 重复的 Excelize 导入

**问题：** 多个文件重复导入相同的 Excelize 模块

```python

from excelize import File

# apps/buyoff/excelize_layout.py
from excelize import File

# apps/export/excel_builders.py
from excelize import File
```

**优化：** 统一导入路径，使用工厂函数

```python
# apps/export/excelize_factory.py
from excelize import File

def create_workbook(sheet_name: str = 'Sheet1') -> File:
    f = File()
    f.NewSheet(sheet_name)
    return f
```

### 🟡 重复的统计计算

**问题：** `compute_cpk` 在多处调用，但参数校验逻辑重复

**当前：**
```python
# apps/analysis/services/statistics.py
def compute_cpk(data, spec_min, spec_max):
    if len(data) < 2:
        return None
    # ... 计算逻辑

# apps/dashboard/views.py
def calculate_metrics():
    if len(df) < 2:
        return None
    cpk = compute_cpk(...)
```

**优化：** 统一参数校验为装饰器

```python
# apps/analysis/services/validators.py
def validate_stats_input(min_samples=2):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(data, *args, **kwargs):
            if len(data) < min_samples:
                raise ValueError(f"至少需要 {min_samples} 个样本")
            return func(data, *args, **kwargs)
        return wrapper
    return decorator

# 使用
@validate_stats_input(min_samples=2)
def compute_cpk(data, spec_min, spec_max):
    # ... 计算逻辑
```

## 八、风险提示

1. **路由变更风险**：合并 app 会改变 API 路径，需同步更新前端 `api/*.ts`
2. **组件拆分风险**：前端组件重组可能破坏现有 import，需全局搜索替换
3. **测试覆盖风险**：重构后需运行 E2E 测试确保功能正常

**缓解措施：**
- 每个 Phase 完成后立即运行 `npm run test:e2e`
- 使用 `git diff` 确认变更范围
- 保留 git 历史，便于回滚
