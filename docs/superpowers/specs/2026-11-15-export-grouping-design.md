# 批量参数分布图：测试项归类 + 多图分页设计规格

- 日期：2026-11-15
- 状态：待复核（未实施）
- 交付物：前端归类 UI + 后端 xlsx 分组/分页装配 + 契约与测试
- 前置（已完成，本工作树）：sheet 命名与总览超链接修复
  （共享规则 `apps/common/sheet_names.py`；链接一律指向实际建出的表）

## 1. 背景与目标

导出物是「总览 + 每个测试项一张 sheet」的 xlsx，审阅者在 Excel/WPS 里批注并回复。
测试项可能上千，sheet 标签爆炸、按名字找图困难；幸而测试项名有稳定家族特征
（`LKG_` 前缀、`CONT_` 前缀、`Trim_Post` 后缀、含 `Trim` 等）。目标：

1. 前端按「前缀 / 后缀 / 包含」规则把测试项归类；
2. 导出时按分类组织 sheet，每页设**最大容量**（默认 50 项/页，尽量装满、超限才拆页），
   避免单表过长与标签过多；
3. 总览里的超链接逐项指向「实际 sheet + 该测试项块的起始行」；
4. 不改变图表渲染与数据口径（含 Site 百分比口径、渲染成本）。

**已拍板的口径（用户 2026-11-15 点定）**

- 路线：保留 xlsx + Excel/WPS 批注（不换 PDF/在线文档/应用内评论）；
- 归类冲突策略：**用户可在 UI 选择，默认「首个命中」**；
- 条件形态：每类多条「前缀/后缀/包含」条件，条件之间是**或**；不提供 AND 组合；
- 匹配默认**大小写不敏感**（ATE 程序存在 `LKG_`/`lkg_` 混写先例）；
- 规则只存前端（按文件），导出时发送**解析后的分组结果**；后端不复制匹配逻辑。

## 2. 实测规模事实（2026-11-15 本机）

| 指标 | 实测值 | 说明 |
|---|---|---|
| 单参数渲染+装配 | ~232ms（KDE 开、dpi=100、4 Site） | 串行作业路径 `workers=1` |
| 单参数 xlsx 体积 | ~45KB（dpi=100） | dpi=200 约 4× |
| 150 项构建 | 34.7s / 6.9MB / RSS +88MB | 含 matplotlib 基线 |
| 外推 1000 / 3000 项 | ≈4min / 45MB；≈12min / 135MB | 低于 60min 作业超时 |

Excel 硬限：工作表数受内存限制（无固定上限）；每表超链接 65,530；唯一格式 65,490。
**结论：分页/归档只改善导航与审阅，不降低总成本（总图片数决定打开/保存时间）。**

## 3. 术语

- **分类（group）**：用户命名的测试项集合，如 `LKG`、`Trim`、`其他`。
- **条件（pattern）**：类型（prefix / suffix / contains）+ 文本，大小写不敏感。
- **块（block）**：一个测试项的「统计表 + 图 + 返回总览链接」，纵向排列。
- **页（chunk）**：一个分类按「每页最大项数」装箱后的一张 sheet，名为 `分类_1`、`分类_2`…
  每页尽量装满 MAX 项，只有最后一页放余数（不是均分）。

## 4. 归类模型

### 4.1 匹配

- 分类命中 = 该类**任一**条件命中（OR）；
- 条件命中：`prefix` 为名称前缀、`suffix` 为名称后缀、`contains` 为子串；统一 `casefold`；
- 未命中任何分类的测试项进入自动分类 **“其他”**（永远排在最后，不可改名/删除）；
- 空分类（无命中）不导出、不占 sheet。

### 4.2 冲突策略（UI 可选，默认首个命中）

1. **首个命中**（默认）：分类按 UI 顺序逐个判断，归入第一个命中的分类；
2. **最具体**：对每个命中的条件计算 `(类型权重, 文本长度)`，后缀=3、包含=2、前缀=1；
   取最高者；并列取 UI 顺序靠前的分类；
3. **允许多属**：测试项可进多个分类；同一张图只渲染一次（按参数缓存 PNG），
   在每个所属分类的块里各嵌入一次（文件体积按出现次数增长）。

### 4.3 预览

UI 实时展示每个分类的命中数 + 前 3 个测试项名；显示冲突数（命中 >1 分类的测试项数）；
显示预计 sheet 数（`1 + Σ ceil(分类命中数 / 每页上限)`）与耗时/体积
（`项数 × 232ms`、`项数 × 45KB`，按当前 dpi 标注为估算）。

## 5. 前端 UI

位置：导出页 `ExportToolsTab.vue`，在「选择参数」之后、「图表显示」之前新增卡片
**「测试项归类」**。组件放 `frontend/src/pages/data/components/export/`，
纯逻辑（匹配/策略/预览计数）放 `frontend/src/pages/data/composables/exportGrouping.ts`
（放 page 目录而非 `src/utils/`，避免 affected 判据升级为全局清单）。

- 分类列表：分类名输入、删除、上下移；每类下若干条件行（类型下拉 + 文本输入 + 删除）；
  「添加分类」「添加条件」按钮；
- 顶部两个全局项：冲突策略下拉（三选一，默认首个命中）、**每页最大测试项数**
  （30/50/100，默认 50）；典型分类（如 30–50 项）各自一张 sheet；
- 「其他」作为只读兜底行展示命中数；
- 帮助提示（必须可见，不能只写进 spec）：大小写不敏感、条件之间为「或」、策略含义；
- 持久化：`safeStorage` 写 localStorage，键 `lqdp.export.grouping.<fileId>`，
  存 `{groups, strategy, maxItemsPerSheet}`；换文件按 fileId 各自加载，无配置时为空；
- 未配置任何分类时，导出请求不携带分组字段，行为与现状一致。

## 6. 后端契约

### 6.1 请求

`POST /api/v1/jobs/export_batch_charts/` 新增可选字段（随现有 `params` 一起进入作业快照）：

```json
{
  "file_id": 1,
  "params": ["LKG_A", "CONT_B", "..."],
  "format": "xlsx",
  "groups": [{"name": "LKG", "params": ["LKG_A", "..."]}],
  "max_items_per_sheet": 50
}
```

- `groups` 由前端解析后发送（含自动「其他」类）；后端不接收也不理解规则；
- 校验：提交层只做结构校验 —— `groups` 内每个参数必须 ∈ 请求 `params`、同一分类内
  不得重复、各分类并集恰好等于 `params`（多属策略下同一参数可出现在多个分类）；
  「参数是否真的存在于文件列」由装配层沿用现有语义过滤（当前 `params` 同样只跳过），
  空分类不建表。违规返回 400，`detail=None`，机器信息走 `extra.field`（沿用守卫错误口径）；
  新错误码 `invalid_groups`、`invalid_page_size`、`groups_not_supported` 需同步
  `frontend/src/utils/error.ts` 的 `ERROR_CODE_MAP`；
- `max_items_per_sheet` 仅允许 30/50/100，其余 400（错误码 `invalid_page_size`），缺省 50；
  **未携带 `groups` 时该字段被忽略**（旧行为不变，归一化函数提前返回）；
- `format=pptx` 时携带 `groups` 返回 400（`groups_not_supported`）：PPT 无 sheet 概念，
  不静默忽略。

### 6.2 装配

- 作业 task 增加 `groups` / `max_items_per_sheet`（`apps/jobs/executor.py`、
  `apps/jobs/runner.py`），传给 `build_batch_charts_xlsx_with_charts`；
- 无 `groups`：保持现状（每项一 sheet），只享受已修复的超链接；
- 有 `groups`：按分类装箱切页（每页写满 MAX、最后一页余数），分类内顺序 = 文件列序
  （与现有 `_collect_param_stats` 的排序一致），不按用户点选顺序；
- 一个测试项的统计只算一次（`_collect_param_stats` 不变），图片按参数缓存一次
  （`_render_chart_pngs` 不变），多属时仅重复嵌入。

## 7. xlsx 版式

### 7.1 总览

- 保持第一张表、名 `总览`；
- 表头在现有 10 列基础上插入「分类」列（位于「参数」之后，第 3 列）；
  多属时并列显示（`LKG / Trim`）；
- 参数单元格超链接指向 `#'<实际 sheet>'!A<块起始行>`；目标来自统一的
  `param → (sheet, row)` 映射，与建表同源；多属时链接指向**第一次出现**的块，
  其余出现位置不重复列总览行（「分类」列已列出全部所属分类）；
- 序号、统计、CPK、良率列口径不变。

### 7.2 数据 sheet 与块

- sheet 名：`unique_sheet_names` 统一分配（共享规则：非法字符清洗、31 字符、
  大小写不敏感去重、保留 `总览`/`History`）；每页基础名 = 分类名 + `_<页码>`；
- 装箱规则：分类 n 项 → `ceil(n / MAX)` 页；第 i 页放
  `min(MAX, n - i*MAX)` 项（前页装满、末页余数），**不均分**；
  例：50 项在 MAX=50 下 1 页、120 项 3 页（50/50/20）；
- 块布局（固定行距，便于登记锚点）：
  - 块起始行 `S`：统计表头；`S+1`：参数名 + Low/High/Unit；`S+1..S+7`：均值/STD/Range/点数/CPK；
  - Site 统计表从 `S` 行第 6 列起写（沿用现有表）；「← 返回总览」在 `S+7` 第 5 列；
  - 图片锚 `A<image_row>`，`image_row = max(S+8, S+2+site行数+1)`；
  - 下一块 `S' = image_row + 24`（450px ≈ 23 行 + 1 行间隔，默认行高 15pt）；
  - `param → (sheet, S)` 登记进映射，总览链接用 `A<S>`；
- 页首块与现有「每项一 sheet」布局逐字一致（`S=1`），保证单页单块外观不变。

## 10. 风险与边界

- 每页容量只是导航收益；总图片数决定 Excel 打开/保存时间，3000 项仍约 135MB（dpi=100）；
- 多属会按出现次数放大文件体积，UI 预览需显示重复数；
- 分类名经清洗后可能变形或加后缀；总览「分类」列展示用户原始分类名，不展示 sheet 名；
- 块间距 24 行按 Excel 默认行高（15pt）估算；用户把默认行高调大时图片可能挤压/重叠
  （现有版式同样如此，不新增风险）；
- 规则存 localStorage：换设备/清缓存会丢，属有意取舍（不扩账号设置契约）。
